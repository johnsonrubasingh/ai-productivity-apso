# APSO Frontend

Next.js App Router frontend for the APSO control center.

## Locked Scope

- Development uses the backend API at `http://localhost:8000/api/v1` unless `NEXT_PUBLIC_API_URL` is set.
- The UI must remain operational with fallback data when the backend is offline.
- Jira and Bitbucket remain read-only in the MVP.
- AWS CI/CD remains mock-only until production credentials and permission scope are supplied.
- AI model calls are never made directly from the frontend.

## Run Locally

```powershell
cd apps/frontend
corepack pnpm install
corepack pnpm dev
```

Open `http://localhost:3000`.

## Production Image

The Dockerfile has separate targets:

- `dev` - local Next.js development server.
- `runner` - standalone production server generated by `next build`.

Use the workspace-level `docker-compose.prod.yml` for production-style builds.

## Pages

- `/` - APSO control center dashboard with integration, findings, readiness, and proof-pack summary.
- `/auth` - browser-session bearer token entry and `/auth/me` verification.
- `/setup` - tenant, project, and work-item setup utilities for backend-backed development.
- `/ingestion` - read-only Jira and Bitbucket extraction plus database ingestion controls.
- `/explorer` - evidence explorer for work items, project health, scanner definitions, and Bitbucket artifacts.
- `/workbench` - backend API workbench for Definition Gap, Code Quality, Coverage, Release Readiness, and Proof Pack routes.
- `/integrations` - integration registry and live connectivity checks for Jira, Bitbucket, AI provider, and runtime readiness.
- `/findings` - AI and scanner findings triage view.
- `/api-contract` - developer-facing list of currently wired backend routes.

## Environment

Create an ignored local file only when overriding defaults:

```text
APSO_BACKEND_API_URL=http://localhost:8000/api/v1
NEXT_PUBLIC_API_URL=http://localhost:8000/api/v1
```

Do not place Jira, Bitbucket, Supabase, model provider, or AWS secrets in frontend environment variables.
